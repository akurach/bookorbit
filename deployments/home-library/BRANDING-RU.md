# Home Library: отдельный патч брендинга

Этот каталог не относится к интеграции Яндекс Книг и не предназначен для upstream pull request. Скрипт создаёт новую одноразовую копию исходников, затем меняет в ней только видимое имя, иконку и раздел About. Исходная рабочая копия BookOrbit не изменяется.

Что меняется в копии:

- основное имя: `Home Library` в браузерном заголовке, PWA title, sidebar и на странице входа;
- простой значок `BookOpen` из уже используемого набора Lucide в sidebar и на странице входа;
- About показывает обязательное сообщение о модифицированной версии, дату и ссылку на точный исходный код этой версии;
- исходное `Powered by BookOrbit`, copyright, AGPLv3, дополнительные условия и ссылка на оригинальный проект сохраняются.

Перед сборкой нужно создать отдельный коммит в форке с функциональным изменением и этим каталогом. В `--source-url` передаётся ссылка ровно на этот коммит, а не на ветку. Так ссылка в About ведёт к исходному коду фактически работающей версии.

Пример после создания такого коммита:

```bash
python3 deployments/home-library/prepare_home_library_branding.py \
  --source /path/to/bookorbit \
  --output /private/tmp/home-library-bookorbit-build \
  --source-url https://github.com/akurach/bookorbit/tree/<полный-хеш-коммита> \
  --modified-date 2026-10-13
```

Затем собирать Docker image нужно из `/private/tmp/home-library-bookorbit-build` обычным процессом BookOrbit. После успешной сборки временную папку следует удалить. Скрипт намеренно требует, чтобы `--output` ещё не существовал, и удаляет частично созданную копию при ошибке.

Ограничения:

- это локальное брендинг-изменение, без новой функциональности, входа через OAuth или импорта;
- manifest PWA, favicon и ярлыки PWA используют добавленный простой SVG-значок книги `home-library-book.svg`; растр-иконки специально не генерируются;
- для обновлений нужно повторно выполнить скрипт из зафиксированного исходника и новой ссылки на коммит.
